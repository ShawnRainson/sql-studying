1. Что такое SQL?

SQL (Structured Query Language) — язык, с помощью которого мы работаем с реляционными базами данных.

Например, у нас есть интернет-магазин и таблица пользователей:

users

id | name  | age | city
---+-------+-----+----------
1  | Alex  | 25  | Moscow
2  | Ivan  | 31  | Kazan
3  | Maria | 22  | Moscow

Мы можем спросить базу:

Покажи всех пользователей.

SELECT *
FROM users;

Или:

Покажи только имена.

SELECT name
FROM users;

Или:

Покажи пользователей старше 25 лет.

SELECT *
FROM users
WHERE age > 25;

То есть SQL — это прежде всего способ описать, какие данные нам нужны и что с ними сделать.

2. SQL и PostgreSQL — не одно и то же

Это очень важно понять с самого начала.

SQL

Это язык.

Пример:

SELECT name
FROM users;
PostgreSQL

Это система управления базами данных (СУБД), которая умеет понимать SQL и работать с данными.

Упрощённо:

          SQL
           ↓
     "Покажи пользователей"
           ↓
      PostgreSQL
           ↓
        users
           ↓
        данные

Можно сказать:

SQL — язык, PostgreSQL — программа, которая этот язык выполняет.

Есть и другие СУБД:

PostgreSQL
MySQL
Microsoft SQL Server
Oracle Database
SQLite

Но SQL является общим языком для работы с реляционными БД, хотя у каждой СУБД есть свои особенности.

3. Что такое база данных?

База данных — это организованное хранилище данных, с которым может работать программа.

Например, интернет-магазин может хранить:

users
products
orders
order_items
payments

Условно:

DATABASE
│
├── users
├── products
├── orders
├── order_items
└── payments

Важно:

база данных — это не просто одна таблица.

Она обычно состоит из множества связанных таблиц.

4. Что такое таблица?

Таблица очень похожа на привычную Excel-таблицу.

Например:

users

---+-------+-----+----------
1  | Alex  | 25  | Moscow
2  | Ivan  | 31  | Kazan

4  | John  | 28  | Berlin

У таблицы есть:

Столбцы
id
name
age
city

Их ещё называют columns.

Строки
1 | Alex  | 25 | Moscow
2 | Ivan  | 31 | Kazan
3 | Maria | 22 | Moscow

Их называют rows.

5. Что такое поле?

Например:

3 | Maria | 22 | Moscow

Значение:

Maria

находится в столбце:

name

Конкретное значение в пересечении строки и столбца часто называют значением поля.

Пока достаточно понимать:

column = столбец
row    = строка
value  = значение
6. Первичный ключ — PRIMARY KEY

Посмотри на нашу таблицу:

id | name  | age
---+-------+----
1  | Alex  | 25
2  | Ivan  | 31
3  | Maria | 22

У каждого пользователя есть уникальный id.

Это позволяет однозначно определить пользователя.

Например:

id = 1

означает конкретного пользователя.

Такой столбец обычно делают первичным ключом:

PRIMARY KEY

Например:

CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name TEXT,
    age INTEGER
);

Пока не переживай из-за CREATE TABLE. Мы подробно разберём его позже.

Главное сейчас:

PRIMARY KEY идентифицирует строку однозначно.

10. SELECT конкретных столбцов

Нам не обязательно получать всё.

Например:

SELECT name
FROM users;

Получим:

Alex
Ivan
Maria
John
Anna

Или:

SELECT name, age
FROM users;

Получим:

name  | age
------+----

Ivan  | 31
Maria | 22
John  | 28
Anna  | 35

То есть:

SELECT name, age

означает:

Верни только name и age.

11. WHERE — фильтрация

Теперь самое интересное.

Допустим:

Покажи пользователей старше 25 лет.

SELECT *
FROM users
WHERE age > 25;

Результат:

id | name | age | city
---+------+-----+-------
2  | Ivan | 31  | Kazan
4  | John | 28  | Berlin
5  | Anna | 35  | Kazan

WHERE отвечает за фильтрацию строк.

Можно представить:

users
  ↓
WHERE age > 25
  ↓
подходящие строки
12. Условия

Например:

WHERE age = 25

Возраст равен 25.

WHERE age > 25

Старше 25.

WHERE age >= 25

25 или старше.

WHERE age < 25

Младше 25.

WHERE age <= 25

25 или младше.

А неравенство можно написать:

WHERE age <> 25

или:

WHERE age != 25

В PostgreSQL оба варианта работают.

13. Текстовые значения

Посмотрим:

SELECT *
FROM users
WHERE city = 'Moscow';

Обрати внимание:

'Moscow'

заключён в одинарные кавычки.

Для SQL это текстовое значение.

Результат:

Maria
14. AND

Можно поставить несколько условий.

Например:

Пользователи старше 25 лет из Казани.

SELECT *
FROM users

Обе проверки должны быть истинными.

15. OR

Например:

Пользователи из Москвы или Казани.

SELECT *
FROM users
WHERE city = 'Moscow'
   OR city = 'Kazan';

Достаточно выполнения хотя бы одного условия.

🧠 19. Очень важная концепция

Сейчас тебе нужно запомнить не столько синтаксис, сколько роли основных конструкций:

🔹 SELECT *

Когда мы пишем:

SELECT *
FROM users;

* означает:

все столбцы

То есть PostgreSQL вернёт всю таблицу.

Но в реальном backend-коде часто лучше явно указывать нужные столбцы:

SELECT id, name, age
FROM users;

Почему?

Потому что если в таблице 20 столбцов, а тебе нужны только 3, нет смысла вытаскивать все 20.

🔹 Несколько столбцов

Столбцы разделяются запятыми:

SELECT name, age
FROM users;

Результат:

Alex   25
Ivan   31
Maria  22
John   28
Anna   35

А вот так нельзя:

SELECT name age
FROM users;

Здесь PostgreSQL может воспринять age как псевдоним для name.

О псевдонимах поговорим чуть ниже.

🔹 AS — псевдоним

Можно сказать PostgreSQL:

«Покажи этот столбец, но назови его в результате по-другому».

Например:

SELECT name AS username
FROM users;

Вместо столбца name в результате увидим:

username
--------
Alex
Ivan
Maria
John
Anna

AS означает примерно:

«назови это как...»

Можно использовать и для вычислений:

SELECT age + 1 AS next_age
FROM users;

Получим:

next_age
--------
26
32
23
29
36

Обрати внимание: значение в базе не изменилось.

Мы просто сказали PostgreSQL:

«При выводе покажи результат этого выражения под именем next_age.»

🧠 Очень важная модель мышления

Запомни пока такую конструкцию:

SELECT что_хочу
FROM откуда_хочу;

Например:

SELECT name, city
FROM users;

Можно мысленно читать:

SELECT → ЧТО?
FROM   → ОТКУДА?

А вчера мы добавили:

WHERE   → КАКИЕ СТРОКИ?
ORDER BY → В КАКОМ ПОРЯДКЕ?
LIMIT   → СКОЛЬКО?

Получается:

SELECT name, city
FROM users
WHERE age >= 30
ORDER BY name ASC
LIMIT 2;

Читаем:

Возьми name и city из users, оставь пользователей от 30 лет, отсортируй по имени и покажи максимум 2.

1. Что делает WHERE?
WHERE отвечает на вопрос:
Какие строки я хочу получить?

Например:
SELECT name, age
FROM users
WHERE age > 25;

PostgreSQL смотрит на каждую строку:
Alex   25 → ❌
Ivan   31 → ✅
Maria  22 → ❌
John   28 → ✅
Anna   35 → ✅

Результат:
Ivan  31
John  28
Anna  35

Очень важно:
WHERE не изменяет таблицу.
Он только говорит:
«Из существующих строк покажи мне те, которые подходят под условие».

2. Операторы сравнения
Ты уже знаешь основные:
Оператор	Значение
=	равно
<>	не равно
!=	не равно
>	больше
<	меньше
>=	больше или равно
<=	меньше или равно


Например:
WHERE age = 25

Только возраст 25.
WHERE age >= 30

30, 31, 32, 33...
Обрати внимание на разницу:
age > 30

❌ 30 не входит.
age >= 30

✅ 30 входит.
Это была одна из наших маленьких неточностей в первом уроке — теперь закрепляем. 😉
3. AND — оба условия должны быть TRUE
Например:
SELECT *
FROM users
WHERE age > 25
  AND city = 'Kazan';

Человек должен одновременно:
возраст > 25
        И
город = Kazan

Проверяем:
Ivan  31 Kazan  → ✅
Anna  35 Kazan  → ✅

Alex:
25 Moscow

Возраст не подходит → ❌
4. OR — достаточно одного условия
SELECT *
FROM users
WHERE city = 'Moscow'
   OR city = 'Berlin';

Получим:
Alex
Maria
John

Потому что пользователь должен быть:
либо из Москвы, либо из Берлина.

⚠️ 5. Главная ловушка: AND + OR
Вот такой запрос:
SELECT *
FROM users
WHERE city = 'Moscow'
   OR city = 'Berlin'
   AND age > 25;

Может выглядеть так, будто мы хотим:
Москва или Берлин, и возраст больше 25.

Но SQL воспринимает это иначе.
У AND приоритет выше, чем у OR.
Фактически:
WHERE city = 'Moscow'
   OR (city = 'Berlin' AND age > 25);

Поэтому если ты хочешь именно:
Москва или Берлин, но возраст обязательно больше 25

нужно использовать скобки:
SELECT *
FROM users
WHERE (city = 'Moscow' OR city = 'Berlin')
  AND age > 25;

🔥 Правило сенсея:
Если смешиваешь AND и OR, лучше ставь скобки явно.
Даже если ты знаешь приоритет операторов.
Так код становится гораздо понятнее человеку.
6. Отрицание — NOT
Иногда нужно сказать:
«НЕ выполняется».

Например:
WHERE NOT city = 'Moscow'

То есть:
пользователи не из Москвы.

Но чаще читаемее написать:
WHERE city <> 'Moscow'

Оба варианта здесь дадут одинаковый результат.
7. WHERE работает с выражениями
Например:
SELECT name
FROM users
WHERE age + 5 > 30;

Мы не обязательно сравниваем просто столбец.
Можно сравнивать выражение.
Для Alex:
25 + 5 > 30
30 > 30
❌

Для Ivan:
31 + 5 > 30
36 > 30
✅

🧠 Важная мыслительная модель
Когда видишь:
WHERE age >= 30

не думай:
«SQL ищет возраст».

Думай:
«SQL проверяет каждую строку: является ли age >= 30 истинным?»

Получается примерно:
Alex   → 25 >= 30 → FALSE
Ivan   → 31 >= 30 → TRUE
Maria  → 22 >= 30 → FALSE
John   → 28 >= 30 → FALSE
Anna   → 35 >= 30 → TRUE

И PostgreSQL оставляет только TRUE.
Это фундаментальная идея SQL. 🧠

🥋 День 4 — NULL в PostgreSQL
1. Что такое NULL?
Представь таблицу пользователей:
CREATE TABLE users (
    id INTEGER,
    name TEXT,
    age INTEGER,
    city TEXT
);


И в ней есть такая запись:
id	name	age	city
1	Alex	25	Moscow
2	Ivan	31	Kazan
3	Maria	NULL	Moscow
4	John	28	NULL
5	Anna	35	Kazan
У Maria неизвестен возраст, а у John не указан город.
Здесь NULL означает отсутствующее или неизвестное значение.
Важно различать:
- 0 — конкретное число;
- '' — пустая строка;
- 'NULL' — обычный текст из четырёх букв;
- NULL — отсутствие значения.
Это совершенно разные вещи!
2. Главная ловушка: = NULL не работает так, как ожидается
Допустим, нужно найти пользователей, у которых неизвестен возраст.
Может возникнуть желание написать:
SELECT *
FROM users
WHERE age = NULL;


Но это неправильно для проверки отсутствующего значения. Такой запрос не вернёт строки с NULL.
Нужно использовать IS NULL:
SELECT *
FROM users
WHERE age IS NULL;


А если хотим найти пользователей, у которых возраст указан:
SELECT *
FROM users
WHERE age IS NOT NULL;


Запомни:
IS NULL
IS NOT NULL


Именно эти конструкции нужны для проверки NULL.
3. Почему NULL особенный?
В SQL логика не ограничивается только TRUE и FALSE. Есть ещё третье состояние — UNKNOWN, то есть «неизвестно».
Например:
SELECT *
FROM users
WHERE age > 20;


Для Maria возраст неизвестен. PostgreSQL не может подтвердить, что её возраст больше 20.
Результат сравнения — UNKNOWN, и такая строка не проходит фильтр WHERE.
Посмотри на примеры:
Выражение	Результат
25 > 20	TRUE
15 > 20	FALSE
NULL > 20	UNKNOWN
NULL = NULL	UNKNOWN
Последняя строка особенно важна: даже сравнение NULL = NULL не возвращает TRUE.
4. Как NULL работает с AND и OR?
Помнишь наши предыдущие уроки?
Теперь добавим к ним третье состояние.
Выражение	Результат
TRUE AND UNKNOWN	UNKNOWN
FALSE AND UNKNOWN	FALSE
TRUE OR UNKNOWN	TRUE
FALSE OR UNKNOWN	UNKNOWN
Почему это важно?
Например:
SELECT *
FROM users
WHERE age > 20
  AND city = 'Moscow';


Если у пользователя возраст неизвестен, результат первого условия будет UNKNOWN. Даже если город — Москва, вся комбинация AND не станет истинной. Строка не попадёт в результат.
5. Как найти пользователей, у которых город неизвестен?
SELECT name
FROM users
WHERE city IS NULL;


А если нужны пользователи, у которых город указан:
SELECT name
FROM users
WHERE city IS NOT NULL;


Это полезно в backend-разработке: например, когда нужно найти пользователей без адреса, заказов без даты доставки или товары без описания.

🥋 День 5 — ORDER BY, LIMIT и OFFSET
Вспомним нашу учебную таблицу users:
id	name	age	city
1	Alex	25	Moscow
2	Ivan	31	Kazan
3	Maria	22	Moscow
4	John	28	Berlin
5	Anna	35	Kazan
1. ORDER BY — сортировка
ORDER BY отвечает на вопрос: в каком порядке показывать строки?

Например, от младшего пользователя к старшему:
SELECT name, age
FROM users
ORDER BY age ASC;


Результат:
name	age
Maria	22
Alex	25
John	28
Ivan	31
Anna	35
ASC — по возрастанию. Это направление используется по умолчанию, поэтому ORDER BY age эквивалентно ORDER BY age ASC.

Теперь от старшего к младшему:
SELECT name, age
FROM users
ORDER BY age DESC;


Результат будет обратным: Anna, Ivan, John, Alex, Maria.

Запомни:
- ASC — от меньшего к большему, от A к Z.
- DESC — от большего к меньшему, от Z к A.
2. Сортировка по нескольким столбцам
Допустим, хотим сначала отсортировать пользователей по городу, а внутри каждого города — по возрасту от старшего к младшему.
SELECT name, age, city
FROM users
ORDER BY city ASC, age DESC;


Как это работает?
1. Сначала PostgreSQL группирует порядок строк по городу в алфавитном порядке.
2. Если у нескольких пользователей один город, среди них сортирует по возрасту от большего к меньшему.
Например, Anna и Ivan оба из Kazan. Anna старше, поэтому она окажется раньше Ivan.

Важный нюанс: второй столбец сортировки используется как дополнительное правило, когда значения первого столбца совпадают.
3. LIMIT — ограничение количества строк
Допустим, нам нужны только три самых старших пользователя:
SELECT name, age
FROM users
ORDER BY age DESC
LIMIT 3;


Результат:
name	age
Anna	35
Ivan	31
John	28
LIMIT 3 означает: вернуть максимум три строки.

Но есть тонкость: без ORDER BY нельзя полагаться на порядок строк. Поэтому если нам нужны именно три самых старших пользователя, сначала задаём сортировку, а затем ограничение.
4. OFFSET — пропустить строки
Представь, что список пользователей отсортирован по возрасту от младшего к старшему:
SELECT name, age
FROM users
ORDER BY age ASC;


Получаем:
1. Maria — 22
2. Alex — 25
3. John — 28
4. Ivan — 31
5. Anna — 35
Теперь пропустим первые две строки:
SELECT name, age
FROM users
ORDER BY age ASC
OFFSET 2;


Результат:
name	age
John	28
Ivan	31
Anna	35
OFFSET 2 означает: пропустить две строки после сортировки.

Можно комбинировать LIMIT и OFFSET.
SELECT name, age
FROM users
ORDER BY age ASC
LIMIT 2 OFFSET 2;


Результат:
name	age
John	28
Ivan	31
То есть мы пропустили две строки, а затем взяли следующие две.
5. Как это применяется в backend?
Представь, что интернет-магазин показывает товары по 10 штук на странице.
- Страница 1: LIMIT 10 OFFSET 0
- Страница 2: LIMIT 10 OFFSET 10
- Страница 3: LIMIT 10 OFFSET 20
Общий шаблон:
SELECT *
FROM products
ORDER BY id ASC
LIMIT 10 OFFSET 20;


Этот запрос выбирает третью страницу при размере страницы 10, если сортировка и данные не меняются между запросами.

Для реального приложения важно также помнить: при добавлении или удалении строк между загрузками страниц записи могут смещаться. В больших системах часто используют пагинацию по ключу (keyset pagination), которую изучим позже.
6. Маленькая ловушка: одинаковые значения
Допустим, у двух пользователей одинаковый возраст. Если написать:
ORDER BY age DESC
LIMIT 3;


порядок пользователей с одинаковым возрастом не гарантирован.

Чтобы сделать сортировку более предсказуемой, можно добавить уникальный идентификатор:
ORDER BY age DESC, id ASC
LIMIT 3;


Сначала сортируем по возрасту, а при совпадении возраста — по id.

Ещё один нюанс PostgreSQL: при сортировке столбца с NULL по умолчанию NULL располагаются в конце при ASC и в начале при DESC. Это можно задавать явно с помощью NULLS FIRST и NULLS LAST.

🥋 День 6 из 60 — IN, BETWEEN, LIKE и ILIKE
Сегодня научимся искать сразу несколько значений, задавать диапазоны и искать текст по шаблону.
1. Оператор IN — выбор из списка
Допустим, нам нужны пользователи из Москвы и Казани.

Вместо длинного условия:
SELECT *
FROM users
WHERE city = 'Moscow'
   OR city = 'Kazan';


Можно написать короче:
SELECT *
FROM users
WHERE city IN ('Moscow', 'Kazan');


Результат: Alex, Ivan, Maria и Anna.

Запомни: IN означает, что значение должно совпасть хотя бы с одним элементом списка.

А NOT IN — что значение не должно совпадать ни с одним элементом:
SELECT *
FROM users
WHERE city NOT IN ('Moscow', 'Kazan');


В нашей таблице результатом будет John из Berlin.
2. BETWEEN — поиск в диапазоне
Найдём пользователей возрастом от 25 до 30 лет:
SELECT *
FROM users
WHERE age BETWEEN 25 AND 30;


Важный нюанс: границы включаются. То есть возраст 25 и 30 тоже подходит.

Это равнозначно условию:
WHERE age >= 25 AND age <= 30


Для поиска за пределами диапазона используем NOT BETWEEN:
SELECT *
FROM users
WHERE age NOT BETWEEN 25 AND 30;


3. LIKE — поиск по шаблону
Здесь начинается самое интересное!
Символ	Значение
%	Любое количество символов, в том числе ноль
_	Ровно один любой символ

Например:
-- Имена, начинающиеся на A
SELECT * FROM users
WHERE name LIKE 'A%';


Результат: Alex, Anna.
-- Имена, заканчивающиеся на a
SELECT * FROM users
WHERE name LIKE '%a';


Результат: Maria, Anna.
-- Имена, у которых второй символ — o
SELECT * FROM users
WHERE name LIKE '_o%';


Результат: John.

В PostgreSQL оператор LIKE чувствителен к регистру: A и a могут давать разные результаты.
4. ILIKE — поиск без учёта регистра
В PostgreSQL есть удобный оператор ILIKE.
SELECT *
FROM users
WHERE name ILIKE 'a%';


Он найдёт и Alex, и Anna, даже если шаблон начинается со строчной a.
